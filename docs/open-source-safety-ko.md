# 공개 저장소 정보 관리

알람표 저장소에는 앱을 빌드하고 업데이트 계보를 검증하는 데 필요한 공개 식별자만 남겨요. 공개 여부와 비밀 여부를 혼동하지 않도록 다음 기준을 사용해요.

## 저장소에 둘 수 있는 값

- Android/iOS 패키지 이름, URL 스킴과 저장 형식 식별자
- 앱 바이너리에도 포함되는 Expo project ID와 공개 Updates URL
- APK와 Play App Signing 인증서의 공개 SHA-256 지문
- 사용자가 방문해야 하는 공개 개인정보처리방침 URL

이 값들은 설치 파일이나 공개 서비스에서 확인할 수 있어 비밀이 아니에요. 다만 불필요한 복제를 막기 위해 `app.json`, `release-policy.json`, `play-release-policy.json`만 단일 기준으로 사용하고 문서·테스트에는 실제 값을 반복하지 않아요.

## 저장소에 두지 않는 값

- 실명, 개인 이메일, 개인 전화번호와 집 주소
- Play Console의 개발자·앱·트랙 숫자 ID와 비공개 검토 자료
- EAS·GitHub·Google 서비스 계정 토큰과 JSON 키
- 키스토어, 인증서 개인키, 비밀번호와 복구 코드
- 로컬 절대 경로, 실기기 일련번호와 원본 진단 로그

앱 지원 연락처는 배포 스토어에서 검증된 연락처로 관리하고 소스에 복사하지 않아요. 보안 취약점은 GitHub의 Private vulnerability reporting을 사용해요.

## 이미 커밋된 정보

현재 파일에서 값을 지워도 이전 커밋에는 남을 수 있어요. 실제 비밀이 커밋됐다면 먼저 폐기·재발급한 뒤 별도 승인을 받아 기록을 정리해야 해요. 공개 식별자나 이미 공개된 인증서 지문만 있는 경우에는 업데이트 계보를 깨뜨릴 수 있는 기록 재작성보다 현재 소스의 중복 제거를 우선해요.
