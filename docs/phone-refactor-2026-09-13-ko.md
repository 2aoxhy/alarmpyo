# 휴대폰 앱 리팩터링 · 2026-09-13

## 범위

워치 앱 계획을 취소하고 휴대폰 앱만 유지한다. 알림 미러링 등 대체 워치 기능도 이번 변경에는 추가하지 않는다. 버전은 1.23(23) 그대로이며 AAB 생성·EAS 업로드·Play 배포·기기 설치는 하지 않는다.

## 변경

- 워치 프로젝트, 공유 프로토콜, 휴대폰 동기화 서비스·scheduler 호출, Wear 의존성·manifest 항목, 전용 검사 도구를 제거했다. 휴대폰 알람·타이머 scheduler와 Android manifest는 워치 추가 전 상태로 복원했다.
- 타이머 상태·남은 시간 기준·관측 시각을 하나의 불변 관측값으로 갱신한다. 카운트다운·울림 시각·접근성 문구는 순수 표시 모델로 분리했다. 시간 변경 직후 이전 tick 시각과 새 시간이 섞이지 않도록 처리했다.
- 카운트다운 컴포넌트를 관측값마다 재마운트하지 않는다. 직접 입력 오류는 별도 state 대신 현재 입력값과 입력 모드에서 계산한다. 기존 1~60분 범위와 도움말 영역은 유지한다.
- 하단바 라벨·아이콘을 공통 컴포넌트로 분리했다. 라벨은 버튼 전체 폭에서 가운데 정렬하고, 이미 계산한 안전 여백을 내비게이션 내부에서 다시 적용하지 않는다. 각 탭의 접근성 이름을 명시하고 장식 아이콘은 별도 초점을 만들지 않는다.
- 배터리 설정은 알람표의 앱 정보 화면으로 먼저 이동한다. 해당 화면에서 사용자가 `배터리 → 제한 없음`을 선택한다. 제조사 비공개 설정 경로나 새 권한은 사용하지 않는다.

AppData, 백업, 알람 ID, 위젯 snapshot, 딥링크, 기존 릴리스 설정은 변경하지 않았다.

## 제거·보관

워치 소스와 전용 문서는 삭제했지만 생성 캐시는 삭제하지 않고 `.artifacts/watch-cancelled-675ce91e37ce410fa3b07ea315fb1760/`로 옮겼다. 기존 `.artifacts/wear-check/`의 개발 APK·검사 보고서는 유지했다. 이 보관물은 앱 배포 소스에 포함되지 않는다. 기존에 설치된 휴대폰 앱이나 사용자 일정 데이터는 건드리지 않았다.

삭제한 신규 워치 소스는 미커밋 파일이므로 Git 자동 복원 지점은 없다. 보관한 APK·캐시는 소스 백업이 아니다. 소스 파일이 제거된 빈 디렉터리는 남아 있다.

## 검증

- 회귀 검사: 워치 연결·의존성 제외와 기존 휴대폰 receiver 유지, 타이머 원자적 관측·1/60분·교체·일시정지·재개·기기 시각 변경, 하단바 전체 문구·안전 여백·장식 초점 제외.
- 문구 정책, 공식 패턴 원본 계약, 전체 TypeScript, 전체 ESLint 통과.
- 전체 Vitest: 234개 파일·1,767개 테스트 통과 (`npm run test -- --maxWorkers=2`). 최초 전체 검사에서 기존 브랜드 이미지 재생성 테스트 한 건이 기본 5초 제한을 넘겼다. 테스트 제한이나 검증 내용을 바꾸지 않고 병렬 실행 수만 줄여 전체를 재검사했다.
- Android 네이티브 검사 통과 (`node scripts/run-native-unit-tests.mjs --prebuild`, JDK 17). 휴대폰 모듈 단위 테스트·앱 manifest 병합·R8 설정·위치 권한 제외를 확인했다. 배포 AAB 생성이나 Play 변형 preflight는 수행하지 않았다.
- 이번 검사는 실제 휴대폰의 글자 측정·키보드·TalkBack 동작을 확인한 것이 아니다. 타이머 시간 변경 후 텍스트 사라짐과 하단바 잘림은 실기기 재확인이 필요하다.
- 개발 환경은 Node 24.19.0/npm 11.17.0, 네이티브 검사는 JDK 17을 사용했다. 릴리스에 고정된 Node 24.16.0/npm 11.13.0 검증이나 Play preflight를 대신하지 않는다. 임시 네이티브 의존성 설치에서 기존 npm 감사 경고 14건(중간 5·높음 9)이 보고되었으며 이번 범위에서 의존성 버전을 변경하지 않았다.
