## 1. 구현 및 확정된 검사

- 공통 입력·버튼·IconTile은 4dp 모서리로 통일했습니다. StatusBanner의 Android 글꼴 여백을 제거해 제목 첫 줄과 아이콘 기준을 맞췄습니다. 모달의 앞쪽 표시를 위한 elevation은 유지했습니다.
- 위젯은 기본 4×1에서 근무·시간과 다음 근무를 표시합니다. 4×2로 늘리면 설정한 보조 정보를 추가합니다. 기존 알람만 표시하는 선택은 보존하며, 근무 중심 4×1에는 보조 알람 행을 넣지 않습니다.
- 위젯 표시 정책을 실제 런처 폭·높이와 글자 크기 기준으로 분리했습니다. 130%에서 축소형 시간 설명을 숨기고, 180% 이상에서는 확장형도 핵심 정보로 줄입니다. 공간이 부족하면 낮은 우선순위 행부터 생략하고 12sp 미만으로 줄이지 않습니다.
- 위젯 패널과 정적 미리보기는 6dp 모서리로 맞췄습니다. 미리보기 캐시의 내부 렌더 버전만 갱신했으며 widget snapshot v2와 기존 view ID·provider·네이티브 API는 유지했습니다.
- 저장·복구·알람·수면·위젯 동기화를 `AppStoreEngine`과 역할별 coordinator로 이관했습니다. React provider는 lifecycle과 구독을 연결하고, 위젯 전송은 AppData를 변경하지 않는 별도 projection으로 유지합니다. AppData v21과 백업·네이티브 wire 형식은 변경하지 않았습니다.
- 화면은 필요한 상태 조각만 구독하도록 이관했습니다. 타이머 조회와 조작은 직렬 실행하며, 이전 화면 세션의 늦은 결과는 현재 화면에 반영하지 않습니다. 직접 입력 중에도 범위·도움말·오류 영역을 유지하고 작은 높이에서는 본문을 스크롤할 수 있게 했습니다.
- 손상된 복구 기록의 조회와 복구 동작을 분리했습니다. 복구는 동일 저장 큐 안에서 격리본을 기록·검증한 뒤 원본이 바뀌지 않았을 때만 지웁니다. 저장 실패, 부분 성공, 패턴 삭제 실패의 복구 경로도 회귀 검사에 포함했습니다.
- 화면 제목과 하위 제목의 접근성 단계를 구분하고, 토글은 부모 행 하나만 읽도록 수정했습니다. 실제 브라우저 접근성 트리에서 설정 마지막 단계의 단일 토글을 확인했습니다.

### 실제 화면 확인 범위

사용자의 기존 localhost 데이터와 분리된 `http://[::1]:4173/` 테스트 저장소에서 첫 설정 3단계, 저장 후 Today, 설정 목록, 재설정 시 현재 패턴 유지, 달력 전환을 실제 브라우저로 조작했습니다. 320px 설정, 390px 설정 단계, 412px Today, 768px 달력에서 배치를 확인했으며 측정한 설정·달력 화면에 가로 넘침이 없었습니다. 페이지 H1과 하위 H2·H3 및 토글의 중복 접근성 노드 제거도 확인했습니다.

이는 계획의 모든 화면×폭×글자 크기 조합을 완료했다는 뜻이 아닙니다. 타이머는 웹에서 Android 전용으로 차단되므로 숫자 키보드·관성 스크롤·안내 문구의 실기기 표시는 아직 검증하지 못했습니다. One UI의 실제 4×1·4×2 RemoteViews 적용, 글자 140~200%, TalkBack, 동작 줄이기, cold start·resume·탭 전환·월 이동 성능 수치는 Samsung 기기에서 확인해야 합니다. 테스트용 서버는 확인 후 종료했으며 기존 사용자 저장소는 바꾸지 않았습니다.

## 4. 배포 재개 시 확인 순서

1. Play 로그인 복구 후 계정 인증·패키지 등록과 모든 트랙·초안·App Bundle Explorer를 확인합니다. 실제 최고 versionCode가 22 이상이면 자동 증분하거나 같은 코드를 재업로드하지 않고 중단한 뒤 사용자와 출시 번호를 결정합니다.
2. 전체 코드·화면 검증을 마친 소스를 커밋하고 깨끗한 상태에서 고정 도구로 Play preflight를 통과시킵니다. EAS `production` 프로필로 code 22 AAB를 한 번 생성합니다.
3. EAS 원본 metadata와 로컬 AAB의 소스 커밋·SHA-256·패키지·버전·서명·targetSdk 36·16KB 설정·R8 mapping을 검증합니다. 업로드 직전에 versionCode 사용 여부를 다시 확인합니다.
4. 동일 AAB를 Internal에 한 번 업로드하고 활성화합니다. Samsung Play 설치본으로 V1.21→V1.22 데이터·권한·알람·타이머·설정 초안·백업 보존, 위젯 두 크기, 글자 확대, TalkBack과 업데이트 복귀 흐름을 확인합니다.
5. 동일 후보의 Play 생성 split ZIP/ELF 정렬·16KB 런타임, R8 연결, 사전 출시 보고서와 오늘→달력→타이머→설정 스크린샷을 새로 검증합니다.
6. 차단 문제가 없으면 기존 Internal 번들을 Console에서 Alpha로 승격합니다. `submit:alpha`로 AAB를 다시 올리지 않습니다. 게시 후 24시간·72시간의 설치 실패·crash·ANR·알람·데이터 이상을 확인합니다. Production은 이번 릴리스 종점에 포함하지 않습니다.

### 2026-09-30 Android 개발자 인증 확인

2026-09-06에 확인한 Android 공식 안내는 대부분의 기존 Play 개발자가 이미 검증한 신원 정보를 사용할 수 있다고 설명합니다. 다만 패키지 이름 등록은 별도로 확인해야 하며, 자동 등록되지 않은 앱을 계속 배포하려면 2026-09-30까지 등록을 완료해야 한다고 명시합니다. 자동 등록 여부를 추정하지 않고 Play Console 홈과 개발자 계정에서 실제 상태를 확인합니다. [Google Play Console에서 Android 개발자 인증·패키지 등록 확인](https://developer.android.com/developer-verification/guides/google-play-console) (문서 갱신일 2026-08-18).

패키지 소유권 확인에서 서명키 관련 작업을 요구하더라도 기존 키를 임의로 교체·회전·내보내지 않습니다. 이번 작업에는 키 변경 권한이 포함되어 있지 않습니다.
