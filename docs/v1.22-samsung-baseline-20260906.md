## 발견 사항

### 1. 타이머 선택 영역이 화면에서 사라짐 — V1.21에서 관찰

실행 중 화면에서 `다른 시간으로 변경` 아래 15분·30분·45분·직접 입력 버튼이 접근성 XML에는 좌표와 함께 남아 있으나 같은 흐름의 화면 캡처에서는 해당 영역이 비어 있었습니다. 사용자 신고와 같은 종류의 렌더링 불일치입니다. XML과 PNG는 순차 수집이므로 정확히 같은 프레임이라고 주장하지 않습니다.

V1.22의 타이머 상태 직렬화·화면 생명주기 및 도움말 레이아웃 보완은 로컬 코드/자동 테스트까지만 검증됐습니다. **이 기기에서 수정 완료라고 판정하지 않습니다.** 후보 설치 후 입력·스크롤·시작·복귀와 실제 화면 캡처를 다시 비교해야 합니다.

### 2. 4×1 위젯을 확장형으로 분류 — V1.22 코드에도 존재

실기기에서 받은 값은 `semAppWidgetRowSpan=1`, `semAppWidgetColumnSpan=4`, `appWidgetMinHeight=100`, `appWidgetMaxHeight=100`입니다. 실제 `appWidgetSizes`도 약 401.07×100.27dp입니다.

현재 `AlarmPyoWidgetSizePolicy.kt`는 높이 96dp 이상을 MEDIUM으로 분류합니다. `AlarmPyoShiftWidgetProvider.kt`는 최소 높이/폭만 전달하고 One UI 행 수나 실제 크기 목록을 반영하지 않으므로 **이 4×1 위젯도 4×2용 세로 구조를 선택**합니다. 이는 실기기 크기 측정과 현재 소스의 대조 결과이며 V1.22 앱을 기기에 설치해 본 결과는 아닙니다.

배포 전 수정 대상입니다. One UI의 유효한 행 수가 1이면 압축형을 선택하고, 행 수를 제공하지 않는 런처에는 별도 공간 기반 정책이 필요합니다. 단순히 96이라는 임계값만 올리는 것으로 모든 런처의 4×1·4×2를 보장할 수 없습니다. 실제 100dp·fontScale 1.15 입력을 회귀 검사에 추가해야 합니다. 이번 점검에서 앱 코드는 수정하지 않았습니다.

### 3. CPU 과다 사용에 따른 기존 앱 종료 이력 — 원인 미확정

기기에 보존된 최근 종료 기록 16개 중 4개가 `EXCESSIVE RESOURCE USAGE / EXCESSIVE CPU USAGE`이며, 2026-09-05~06의 백그라운드 `state=empty` 상태였습니다. 확인한 기록은 보존 범위에 한정되므로 전체 발생 횟수를 뜻하지 않습니다. 이 기록만으로 타이머·위젯·알람 중 어느 기능이 원인인지, 알람 누락이 있었는지 판단할 수 없습니다.

점검 중 현재 프로세스의 오류 로그 조회는 빈 결과였고 CPU 순간 샘플은 0%였습니다. 이는 장시간 백그라운드 안정성이나 crash/ANR 0건을 증명하지 않습니다. V1.22 후보에서 background/resume 및 화면 비활성 시 주기 작업을 재검사해야 합니다.

현재 V1.22 소스의 Today·타이머·달력 ticker는 탭 포커스와 앱 활성 상태에 따라 정리되고, 타이머 만료 조회도 최대 8회로 제한됩니다. 읽기 전용 코드 검토에서 명백한 백그라운드 무한 반복은 확인하지 못했습니다. 다만 이미 예약된 500ms 알람 동기화가 백그라운드 전환 후 한 번 실행될 수 있습니다. 이를 CPU 종료 이력의 원인으로 단정하지 않습니다.

## 증거와 남은 검사

원본은 Git에서 제외되는 `.artifacts/device-baseline-v121-20260906/`에 보존했습니다. 실제 근무 정보가 포함된 개인용 기준 자료이며 스토어 자산으로 게시하지 않습니다.

- `today.xml`, `today.png`: 기존 Today 화면
- `timer.xml`: 첫 타이머 탭 상태
- `timer-custom.xml`, `timer-custom.png`: 직접 입력 탐색 뒤 관찰한 실행 중 화면과 렌더링 불일치
- `device-diagnostics.json`: 설치 정보, 권한, 앱 종료 이력, 현재 프로세스 오류 조회
- `widget-options.txt`: 앱 위젯의 One UI options 및 배터리 예외 확인. diagnostics의 최초 배터리 배열은 필터 열 위치가 잘못되어 비어 있었으며, 이 파일의 재확인 결과가 유효함

V1.22 후보별 AAB SHA·EAS build ID·Play 서명 확인, Play→Play 업그레이드 데이터·권한 보존, 위젯 4×1/4×2 실제 표시, 글자 140~200%·TalkBack, 타이머 소리/진동/화면 꺼짐·재부팅, 알람·복구·패턴·PNG 검증은 남아 있습니다. 현재 점검을 공식 `play-physical-device` 통과 JSON으로 변환하거나 V1.22 스크린샷으로 재사용하지 않습니다.
