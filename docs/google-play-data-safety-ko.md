# 알람표 Google Play 데이터 보안·정책 작성 초안

이 문서는 Play Console 입력을 돕는 기술 검토 초안이에요. 저장소만 보고 확정 답변으로 제출하지 않고, **최종 Play AAB와 Play가 생성한 APK**의 SDK·네트워크 동작·개인정보 처리방침을 제출 직전에 다시 대조해요. Google의 정의와 예외를 우선 적용해요. [Google Play 데이터 보안 공식 안내](https://support.google.com/googleplay/android-developer/answer/10787469?hl=ko)

## 앱 자체 처리 기준

- 계정 생성: 없음
- 광고 SDK: 없음
- 사용자 분석 SDK: 없음
- 근무표·메모·알람·타이머 설정: 기기 내부 저장
- 백업·근무 설정 공유: 사용자가 직접 기능을 실행하고 대상 앱·파일 위치를 선택할 때만 외부 파일로 전달
- 공식 근무 패턴: 사용자가 패턴 보관함을 열거나 새로고침할 때만 GitHub Pages의 서명 파일 세 개를 HTTPS로 조회하며, 기기 내 근무 자료는 요청에 포함하지 않음
- 앱 데이터 삭제: 설정의 데이터 초기화 또는 앱 삭제
- 자체 서버: 없음

사용자 주도 공유가 Play의 “수집” 또는 “공유” 예외에 해당하는지는 실제 공유 화면과 데이터 보안 양식의 최신 설명을 대조해 답해요. 앱이 자동으로 전송한다고 오해할 수 있는 문구를 사용하지 않아요.

## 외부 서비스와 최종 AAB 재검토

알람표는 `app.json` 기준으로 `expo-updates` 자동 확인이 활성화되어 있고, Play 배포판도 앱 실행 시 `https://u.expo.dev/...`로 HTTPS 요청을 보내요. 따라서 현재 구성을 유지하면 데이터 보안 양식에 “수집하는 데이터 없음”을 바로 선택하면 안 돼요. Google은 SDK가 기기 밖으로 전송하는 가명 데이터도 “수집”에 포함해요.

Expo의 현행 공개 설명은 EAS Update 요청에 기기 운영체제, 개발자 프로젝트 ID와 앱 설치별 무작위 토큰이 포함될 수 있다고 안내해요. Expo 개인정보 처리방침은 서비스 요청의 IP 주소, 오류·성능 지표를 처리할 수 있다고 설명해요. 최종 네트워크 관찰과 Expo의 최신 정책을 바탕으로 다음 기술 정보의 실제 처리를 확인해요.

- 기기 운영체제와 앱·업데이트 버전 정보
- 업데이트 요청을 구분하는 설치 식별자 또는 토큰
- IP 주소와 네트워크 활동 정보
- 업데이트 설치 실패·성능·오류 진단 정보

제출 직전 다음 순서로 확인해요.

1. `npm run release:verify:aab`로 검증한 AAB의 SDK와 JavaScript 번들을 확인해요.
2. Play 내부 트랙에서 설치한 최종 APK를 최초 실행·재실행·업데이트 실패 상황으로 나눠 관찰해요.
3. Expo 정책의 데이터 유형·보존·공유 대상을 현재 버전과 대조해요. [Expo 개인정보 처리방침](https://expo.dev/privacy), [Expo 개인정보 설명](https://expo.dev/privacy-explained)
4. 관찰된 데이터 유형만 Play Console에 기록하고, 확인하지 못한 처리는 “없음”으로 추정하지 않아요.

현재 코드와 Expo 공개 설명을 기준으로 한 **Console 항목별 검토표**는 다음과 같아요.

| Play Console 데이터 유형 후보 | 현재 근거 | 제출 전 판단 |
| --- | --- | --- |
| 기기 또는 기타 ID | EAS Update는 설치별 무작위 토큰을 업데이트 요청에 사용한다고 설명해요. Google은 Firebase 설치 ID처럼 개별 앱 설치와 관련된 식별자를 이 유형의 예로 들어요. | **현재 임시 답변은 `수집·필수·앱 기능`이에요.** Expo가 개발자의 지시에 따라 처리하는 서비스 제공자인지 최종 계약·정책으로 확인한 뒤에만 `공유 안 함` 예외를 적용해요. |
| 앱 정보 및 성능·진단 | Expo 정책은 운영체제, 오류와 성능 정보를 처리할 수 있다고 설명해요. | 최종 APK에서 실제로 보내는 세부 유형만 선택하고, 단순히 SDK가 포함됐다는 이유로 모든 진단 항목을 선택하지 않아요. |
| 앱 활동 | Expo 개인정보 문구는 서비스 전반의 앱 상호작용 통계를 언급하지만 EAS Update 최종 APK에 적용되는 범위는 별도 확인이 필요해요. | 실제 요청·Expo의 SDK별 안내에서 확인된 항목만 신고해요. |
| 근무표·메모·알람·타이머 설정 | 앱 코드에서 기기 내부에만 저장하고 업데이트 요청에 싣지 않아요. | 최종 네트워크 관찰에서도 전송되지 않으면 수집·공유하지 않음으로 답해요. |
| 건강 정보 | 수면 기록을 받지 않고 근무 일정으로 안내 시각만 기기에서 계산해요. | 최종 동작이 같다면 건강 데이터 수집 없음으로 답하되, 아래 건강 기능 선언은 별도로 완료해요. |

Google은 IP 주소의 신고 유형이 실제 사용 방식에 따라 달라진다고 안내해요. 따라서 `IP 주소·네트워크 활동`을 존재하지 않는 단일 Console 항목처럼 제출하지 않아요. `진단`, `앱 상호작용` 항목은 Expo의 서비스 전반 정책만 보고 선택하지 말고, **해당 Play 산출물의 EAS Update 요청에 적용되는지** 확인해요.

Google의 정의에서 앱이 SDK를 통해 기기 밖으로 전송하는 것은 수집이고, 서비스 제공자 전송 예외는 “수집”이 아니라 “공유” 판단에만 적용돼요. 백업·근무 설정 파일은 사용자가 직접 대상 앱을 고르고 개발자가 받지 않는 현재 구현이 유지되면 Google의 사용자 시작 전송 예외를 검토할 수 있어요.

## 건강 기능 선언과 데이터 보안을 분리해요

수면 데이터를 수집하지 않더라도 수면 준비 시점을 안내하는 기능 자체가 `Sleep Management`로 분류될 수 있어요. 건강 기능 선언과 데이터 보안의 데이터 수집 문항을 서로 대신 답하지 않아요.

- 모든 Play 앱은 건강 앱 선언을 완료해요.
- 알람표가 제공하는 범위는 **기기 내 근무 일정에서 계산한 수면 준비 시점과 일반 알림**까지예요. 수면 시간·패턴·질을 입력받거나 측정·추적하지 않고, Health Connect·센서·의료 데이터 권한을 사용하지 않아요.
- `Sleep Management`는 수면 패턴과 질을 개선·추적하는 앱을 포함하는 항목이에요. 알람표는 주요 기능이 근무 일정이지만 수면 준비 알림을 스토어에서 명시하므로, Play 지원의 반대 확인이 없다면 이 항목만 보수적으로 신고해요. 의료·연구·다른 건강 기능은 선택하지 않아요.
- 앱과 공개 개인정보 처리방침에는 “의료기기가 아니며 질환을 진단·치료·치유·예방하지 않는다”는 안내와, 의료 조언이 필요하면 의료 전문가와 상담하라는 안내를 일관되게 제공해요. 스토어 설명은 실제 근무 일정·알림 기능만 간결하게 안내해요.
- 개인정보 처리방침은 건강 관련 기능과 수집하지 않는 데이터도 실제 동작에 맞춰 설명해요.

[건강 앱 선언 공식 안내](https://support.google.com/googleplay/android-developer/answer/14738291?hl=ko)와 [건강 콘텐츠 정책](https://support.google.com/googleplay/android-developer/answer/16679511?hl=ko)을 기준으로 검토해요.

2026년 9월 30일부터 적용되는 Play Console 요구사항에는 건강 앱 등 지정 서비스의 조직 계정 등록 요건이 있어요. 분류와 계정 유형이 미확정이면 production을 시작하지 않아요. [Play Console 요구사항](https://support.google.com/googleplay/android-developer/answer/10788890?hl=ko)

## 보안·삭제 답변 초안

- 전송 중 암호화: 예. 업데이트 통신과 개인정보 처리방침 페이지는 HTTPS를 사용해요. 최종 네트워크 확인에서 평문 통신이 없어야 해요.
- 계정 생성: 아니요. 따라서 외부 계정 삭제 URL 의무는 해당하지 않지만, 데이터 보안 양식의 삭제 문항은 별도로 답해요.
- 데이터 삭제 요청: 설정에서 초기화하면 현재 근무표·메모·설정이 초기화되고 실행 중인 타이머가 취소되지만 복구를 위한 **초기화 직전 근무 자료의 내부 안전 백업이 남아요.** 앱을 삭제하면 현재 자료와 내부 안전 백업이 함께 삭제되고, 외부로 내보낸 백업은 저장한 위치에서 사용자가 직접 삭제해야 해요. 이 기기 내 초기화를 Expo가 처리한 설치 토큰·기술 정보의 **서버 삭제 요청 수단**이라고 답하지 않아요. Expo의 보관·삭제 정책과 요청 절차를 확인한 뒤 양식의 삭제 지원 여부를 확정해요.
- 독립적인 보안 검토: 별도 공인 검토를 받지 않았다면 아니요로 답해요.
- 아동 대상 여부: 아니요. 대상 연령과 스토어 콘텐츠가 성인 교대 근무자 설명과 일치해야 해요.
- 데이터 암호화 백업: 사용자가 직접 만든 백업 파일의 암호화 방식과 복원 경로가 실제 앱 설명과 일치해야 해요.

## 공개 개인정보 처리방침 준비 상태

`public/privacy-policy.html`에는 현재 앱과 일치하는 한국어 본문이 준비되어 있습니다. 앱 안의 `src/app/privacy.tsx`와 다음 범위를 같게 유지합니다.

- 알람표·개발자 이름과 문의 이메일
- 기기 내 저장, 사용자 시작 공유·백업
- EAS Update 통신과 Expo가 처리할 수 있는 기술 정보
- GitHub Pages에서 공개 방침 페이지를 열 때의 IP 주소 보안 로그와 앱 데이터 전송의 구분
- 패턴 보관함 진입·새로고침 때의 공식 패턴 HTTPS 조회, 백그라운드 주기 조회 없음, 기기 내 근무 자료 미전송
- 수면 준비 시점의 기기 내 계산, 건강 데이터 미수집, 비의료 안내
- 권한, 보관·삭제, 아동 대상 아님, 시행일

Play Console과 `play-release-policy.json`에는 공개·확인한 `https://2aoxhy.github.io/alarmpyo/privacy-policy.html`이 등록되어 있고 Play 정책은 `active`입니다. V12의 공식 패턴 수동 조회 설명과 2026년 8월 20일 시행일을 반영한 본문은 2026년 8월 20일 GitHub Actions 실행 `#5`에서 다시 게시했습니다. 게시본 SHA-256이 로컬 원본과 일치하고 공개된 공식 패턴 세 파일의 P-256 서명이 모두 유효함을 확인했습니다. 이후 본문·시행일·공식 패턴 source 또는 공개키가 변경되면 같은 검증 절차를 다시 완료해야 합니다.

GitHub Pages의 방문자 IP 보안 로그는 사용자가 웹 개인정보처리방침을 열거나 앱에서 공식 패턴을 조회할 때 발생하는 호스팅 처리입니다. 공식 패턴 요청에는 근무표·메모·알람·타이머 설정을 포함하지 않고 백그라운드 주기 조회도 하지 않습니다. 앱의 데이터 보안 양식은 이 사용자 시작 조회와 EAS Update를 포함한 최종 Play 설치본의 실제 네트워크 동작을 별도로 관찰해 작성합니다.

## 권한·API 선언과 영상 증거

- `USE_EXACT_ALARM`: 사용자가 설정한 교대 근무 기상 시각과 15분·30분·45분·60분 타이머 목표 시각에 정확히 울리는 핵심 알람 기능으로 설명해요. 대략적인 백그라운드 작업에 사용하지 않아요. [정확한 알람 공식 안내](https://developer.android.com/about/versions/14/changes/schedule-exact-alarms?hl=ko)
- `USE_FULL_SCREEN_INTENT`: 사용자가 켠 근무·타이머 알람을 잠금 화면에서 즉시 인지하고 끌 수 있게 하는 알람 핵심 기능으로 설명해요.
- `FOREGROUND_SERVICE_MEDIA_PLAYBACK`: 근무·타이머 알람 발생 후 사용자가 끄거나 다시 알림을 선택할 때까지 알람음을 안정적으로 재생하는 사용자 인지 기능으로 설명해요.
- Play AAB에는 `REQUEST_INSTALL_PACKAGES`, direct APK 설치 Provider·클래스·화면이 포함되지 않아야 해요.

Android 14 이상 대상 앱은 FGS 유형마다 기능 설명, 작업 지연·중단 영향, 사용자가 기능을 시작하는 과정을 보여주는 영상 링크를 제공해야 해요. 전체 화면 Intent도 핵심 알람 용도로 신고해요. [FGS·전체 화면 Intent 선언 공식 안내](https://support.google.com/googleplay/android-developer/answer/13392821?hl=ko)

검토 영상은 실제 Play 내부 트랙 설치본에서 다음 흐름을 끊김 없이 보여줘요.

1. 사용자가 근무 알람을 켜고 시각을 저장해요.
2. 운영체제에 정확한 알람이 예약된 상태를 확인해요.
3. 앱을 닫고 화면을 잠근 뒤 예정 시각에 전체 화면 알람과 알람음이 동작해요.
4. 사용자가 끄기 또는 5분 뒤 다시 울리기를 선택해요.
5. 알림·전체 화면 접근이 거부된 경우 앱이 성공으로 오인하지 않고 제한 상태를 안내하는 화면도 별도로 보여줘요.

영상 링크는 Play 검토자가 로그인이나 접근 요청 없이 볼 수 있어야 하고, 설명란에 versionCode·기기·Android 버전을 적어요. 같은 영상으로 여러 선언을 설명하더라도 각 기능의 시작 단계와 사용자 영향을 명확히 구분해요.

## 제출 차단 체크리스트

다음이 모두 확인되지 않으면 데이터 보안·정책 양식을 제출하지 않아요.

- 최종 AAB와 EAS 원본 SHA-256·소스 커밋 일치

- 앱·스토어·개인정보 처리방침의 수집·공유·삭제 설명 일치
