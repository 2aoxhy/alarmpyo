# 알람표 (AlarmPyo)

교대 근무 일정과 알람을 간편하게 관리하는 독립 앱입니다. 계정 없이 근무 자료를 휴대폰에 저장하며, 사용자가 요청할 때만 공식 패턴과 출퇴근 환경 브리핑에 필요한 공개 데이터를 HTTPS로 조회합니다.

`알람표`는 주간·교대 근무자의 근무표, 기상 알람, 15분·30분·45분·60분 타이머, 출퇴근 날씨·공기질, 수면 준비와 위젯을 한곳에서 관리하는 앱입니다.
공개 저장소에 남겨도 되는 식별자와 제외해야 하는 개인정보·자격증명 기준은 [`docs/open-source-safety-ko.md`](docs/open-source-safety-ko.md)에서 확인해요.

## 근무 방식

- `주간 고정`
- `2조 2교대`, `3조 2교대`, `3조 3교대`, `4조 2교대`, `4조 3교대`
- `기타`: 주간·오후·야간·휴무를 조합한 1~42일 반복 주기

교대제 이름은 대표 예시이며 첫 설정에서 회사의 실제 반복 순서와 시작·종료시간을 확인하고 바꿀 수 있어요. 신규 2교대는 `07:00~19:00 / 19:00~다음 날 07:00`, 3교대는 `07:00~15:00 / 15:00~23:00 / 23:00~다음 날 07:00`을 제안합니다. 기존 사용자가 저장한 근무 시간과 반복 순서는 업데이트가 임의로 덮어쓰지 않아요.

근무 방식은 설정에서 변경할 수 있어요. 변경 전에 현재 근무표를 자동 백업하고, 오늘 이후 직접 변경한 근무와 시간은 새 근무 방식에 맞게 정리해요. 메모, 휴가·교육·예비군 일정과 과거 날짜의 직접 변경은 유지해요.

저장할 때 본문과 최근 정상본은 Android 비동기 저장소에, 별도 정상본 두 세대는 앱 문서 파일에 교대 저장합니다. Android 비동기 저장소는 24MB로 구성하고 전체 백업 파일은 4MB로 제한해 복구용 복사본의 여유 공간을 확보합니다. 앱 삭제나 휴대폰 분실에는 앱 문서 파일도 함께 사라지므로 설정의 `전체 백업 저장하기`로 만든 파일을 별도로 보관해야 합니다.

## 주요 기능

- 연차·교육·예비군을 기본 근무표를 바꾸지 않고 날짜별 예외 일정으로 기록합니다.
- 달력에서 날짜별 근무와 예외 일정을 확인합니다. 해당 연도의 법정공휴일과 사용자가 지정한 1~31일 급여일 및 직전 영업일 조정 결과도 함께 표시합니다.
- 알람이 울리면 5분 뒤 예비 알람을 한 번만 자동으로 예약합니다. 알람 끄기는 예비 알람까지 취소하며, 직접 다시 울리기를 선택해도 같은 한 번으로 합쳐 중복되지 않습니다.
- 설정에서 최근 알람 재생·끄기·5분 뒤 다시 울리기·실패·재시도 기록을 확인합니다. 기록은 휴대폰 안에 최근 12건만 보관합니다.
- Android 홈 화면 위젯은 4×1 전용으로 고정됩니다. 왼쪽에는 오늘 날짜와 현재 상태, 오른쪽에는 다음 근무만 분리해 표시하며 주간·야간·휴무에 맞는 아이콘과 색상을 사용합니다.
- 동료에게 근무 방식·기준 날짜·근무 시간·알람 선행시간만 전용 파일로 공유합니다. 메모, 날짜별 변경, 예외 일정, 테마와 알람 기록은 포함하지 않으며 가져오기 전에 내용을 확인하고 현재 전체 데이터를 자동 백업합니다.
- 알람 예약 수·정확 알람·전체 화면·알림 권한·알람 음량·배터리 제한과 설치된 위젯 상태를 자동 점검합니다. 정상일 때는 숨기고 확인이 필요한 항목이 있을 때만 오늘 화면에 안내합니다.
- 설정한 출근 알람 시간에 맞춰 기상·수면·출근 준비 루틴을 함께 계산합니다.
- 하단 타이머에서 15분·30분·45분·60분 뒤 기존 알람음과 진동으로 알려주며, 한 번에 하나만 실행합니다. 일시정지·재개·초기화를 지원하고 재부팅 뒤에도 남은 시간을 복구합니다.
- 선택한 지역의 기상청 예보와 에어코리아 실측 공기질을 출퇴근 시각에 맞춰 오늘 화면에서 확인합니다. 자동 위치는 대략적인 위치만 사용하며 직접 지역을 선택할 수도 있습니다.
- 공식 서명 패턴과 1~42일 사용자 패턴을 보관하고, 적용 전에 달력에서 변경 전·후와 날짜별 직접 수정 처리 방식을 확인합니다. 가져오기와 적용은 분리되며 근무 시간·알람·권한은 외부 패턴으로 변경하지 않습니다.

## 배포 번호

V14까지는 `1.0.x`를 `V00`으로 표시했고, V15부터는 사용자·Play 버전 `1.x`와 릴리스명 `Vx`를 맞춥니다. 현재 후보는 `1.15(15) · V15`이며 npm 내부 SemVer만 `1.15.0`을 사용합니다. V13은 Play Alpha에, V14는 Play internal에 배포되어 있고 V15는 같은 패키지 계보의 다음 후보입니다. V09는 사용하지 않았고 V11은 Play에 업로드하지 않았습니다. 화면에는 현재 실행 중인 내장 번들이나 무선 업데이트의 생성일도 함께 표시하며, 생성일을 알 수 없는 개발 환경에서는 최신이라고 단정하지 않습니다.

## 실행

```powershell
npm ci
npm start
```

Node.js 24.16.0과 함께 배포된 npm 11.13.0을 사용해요. 휴대폰에서 엑스포 고로 QR 코드를 스캔하거나 다음 명령으로 각 환경을 열 수 있습니다.

```powershell
npm run android
npm run ios
npm run web
```

## 검사

```powershell
npm run check
```

처음 내려받은 작업 폴더에서는 의존성을 새로 설치한 상태까지 포함해 다음 릴리스 검사를 실행합니다.

```powershell
npm run release:check
```

이 검사는 운영 의존성의 높은 등급 이상 취약점도 함께 확인해요. Expo와 함께 사용하는 `xcode`의 UUID 생성기는 보안 수정이 포함된 `uuid 11.1.1`로 고정해요.

일정은 기기에만 저장되고 서버나 회원가입을 사용하지 않습니다. 외부 백업은 기존 JSON 파일과 비밀번호로 보호하는 `.alarmpyo` 암호화 파일 중에서 선택할 수 있어요. 암호화 백업 비밀번호는 기기나 서버에 저장하지 않으므로 별도로 기억해야 해요. 출근 준비 알람은 휴대폰의 알람 음량으로 울리는 알람표 전용 전체 화면 알람으로 동작합니다.

## 배터리 절약

화면이 보이지 않거나 앱이 백그라운드에 있으면 시간 갱신과 장식 애니메이션을 멈춥니다. 근무 아이콘과 시간대 전환은 화면을 열 때 한 번만 재생합니다. 알람표는 앞으로 90일의 근무 계획을 네이티브 알람 계층에 보관하고 그중 다음 3개만 운영체제에 정확하게 예약합니다. 알람이 울리면 앱을 열지 않아도 다음 근무 알람을 자동으로 보충합니다. 앱 복귀 시에는 날짜·시간대·권한·실제 예약 상태가 달라졌을 때만 계획을 다시 동기화하며, 업데이트는 앱을 시작할 때 확인합니다. 알람 화면에서는 배터리 사용 제한 상태를 별도로 안내하지만 시험 알람 자체를 막지는 않습니다.

안드로이드 APK에 포함된 알람표 자체 근무·타이머 알람이 앱을 닫은 상태에서도 알람 음량과 진동으로 울리고, 휴대폰 재부팅 뒤에는 저장된 예약을 자동으로 복구합니다. 잠금 화면에서도 끄기와 5분 뒤 다시 울리기를 제공하며, 첫 알람 뒤에는 5분 예비 알람을 한 번만 준비하고 끄기를 누르면 함께 취소합니다. 이 기능은 네이티브 모듈이 필요하므로 엑스포 고가 아니라 설치한 APK에서 시험해야 합니다.

## 직접 설치용 APK와 업데이트

direct APK와 Play AAB의 분리 구성, 새 Expo 프로젝트 연결과 두 배포판의 인증서 지문은 준비됐어요. direct 공개 정책의 남은 blocker는 production Hosting URL이며, `release-policy.json`의 `releaseState`가 `blocked`인 동안 빌드 결과를 운영으로 승격하거나 OTA를 게시하지 않아요. Play는 공개 개인정보처리방침과 Google 관리 별도 App Signing 계보를 확인해 독립 정책을 활성화했어요. 자세한 절차는 [`docs/google-play-release-runbook-ko.md`](docs/google-play-release-runbook-ko.md)를 따라요.

production Hosting의 실제 HTTPS 기준 URL을 기록한 뒤에만 direct 공개 차단을 해제해요. 이 direct 차단은 Play를 자동으로 막지 않으며, Play에는 실제 공개·검증한 개인정보처리방침 HTTPS 주소를 별도로 기록해요. Play App Signing도 direct 인증서를 자동으로 가정하지 않고 선택한 전략과 최종 인증서 SHA-256을 별도 정책에 기록해요. same-signer일 때만 direct→Play 교차 업데이트 검사를 요구하고, 별도 signer라면 외부 백업 후 제거·새 설치·복원 경로를 안내해요.

예제 UUID·주소나 이전 앱의 서명 인증서를 대신 넣지 않아요. 차단을 해제한 뒤 APK 파일명은 `AlarmPyo_YYYYMMDD.apk`, 환경 변수는 `ALARMPYO_*` 접두사를 사용하고, EAS 증거·Samsung 실기기·Android 12~16 검증을 모두 완료한 뒤 첫 원장 항목을 추가해요. 자세한 절차는 [`docs/release-provenance.md`](docs/release-provenance.md)를 따라요.

## 정적 배포 산출물 정리

정적 화면을 다시 내보낼 때 기존 `dist`를 그대로 덮어쓰면 삭제된 화면이나 오래된 번들이 남을 수 있어요. 내보내기 직전에 전용 스크립트로 `dist`만 정리해요. 기본 실행은 파일 수와 용량만 확인하며 아무것도 삭제하지 않아요.

```powershell
node scripts/prepare-static-export.mjs
npm run clean:export
npm run export:web
```

정리 스크립트는 프로젝트 루트의 `dist` 외에는 받지 않아요. 경로가 프로젝트 밖을 가리키거나 폴더 안에 심볼릭 링크가 있으면 중단해요. `public`, APK 보관 폴더와 소스 파일은 정리 대상에 포함하지 않아요.

## APK 보존 정책

새 AlarmPyo 릴리스 원장은 현재 비어 있어요. 첫 릴리스 뒤에는 공개 APK 보관 폴더에서 `latest-android.json`, 직전 `previous-android.json`, 최근 3개 버전을 보호해요. 기본 검사는 정리 대상을 보고만 하고, 승격이 완전히 검증된 뒤에만 오래된 APK를 자동으로 정리해요.

```powershell
npm run audit:artifacts
node scripts/audit-public-apks.mjs --keep-recent 3 --json
node scripts/audit-public-apks.mjs --keep-recent 3 --apply
```

검사할 때 현재 APK의 파일 크기·SHA-256·운영 서명 인증서를 배포 정책과 비교해요. `--apply`는 모든 검사가 통과한 경우에만 보호 대상 밖의 파일을 정리하며, 현재·직전 APK는 삭제하지 않아요.

## 안드로이드 실기기 출시 체크리스트

### 배포 전

- `release-policy.json`의 실제 Expo·Hosting·서명 값이 채워지고 `releaseState`가 `active`인지 확인해요.
- `npm run release:preflight`가 통과하는지 확인해요.
- `node scripts/audit-public-apks.mjs`에서 오류가 없는지 확인해요.
- 첫 릴리스에서는 이전 앱의 APK·원장·서명 인증서를 AlarmPyo 계보에 섞지 않아요.
- 후속 릴리스부터는 이전 AlarmPyo 운영 APK를 삭제하지 않고 같은 패키지명과 서명으로 새 APK를 준비해요.
- APK의 버전 이름·버전 코드·파일 크기·SHA-256이 배포 정보와 같은지 확인해요.

### 삼성 휴대폰에서 설치·업데이트

- 첫 릴리스는 새 설치 흐름을 확인하고, 후속 릴리스는 기존 AlarmPyo 위에 설치해 근무표·메모·설정이 유지되는지 확인해요.
- 이미 허용한 알림·정확 알람·전체 화면 알람 권한이 유지되는지 확인해요. 안드로이드가 별도 확인을 요구하면 앱의 권한 안내가 정확한 설정 화면을 여는지도 확인해요.
- 설정의 앱 업데이트에서 APK 다운로드, 무결성 검사, 안드로이드 설치 화면 열기와 설치 후 재실행까지 확인해요.
- 새로 설치한 휴대폰에서는 첫 근무일 설정과 기본 알람 권한 안내를 처음부터 확인해요.

### 알람 안정성

- 앱을 최근 앱 목록에서 닫은 상태와 화면이 잠긴 상태에서 실제 근무 알람이 울리는지 확인해요. 안드로이드 설정에서 `강제 종료`한 상태는 별도 예외로 기록해요.
- 휴대폰을 재부팅한 뒤 예약된 알람이 복구되고 다음 3개 알람이 올바른지 확인해요.
- 주간·야간·교육 일정의 알람 시각과 30분·1시간·90분·2시간·3시간 전 설정을 각각 확인해요.
- 알람 끄기 뒤 5분 예비 알람이 함께 취소되고, 다시 울리기를 선택했을 때는 한 번만 울리는지 확인해요.
- 잠금 화면 전체 알람, 알람 음량, 진동과 배터리 사용 제한 안내를 확인해요.

### 화면·데이터

- 오늘·달력·설정 화면을 다크 전용 테마와 큰 글자 설정에서 확인해요.
- 달력의 주간·야간·휴무·교육·예비군·공휴일·급여일이 겹치지 않는지 확인해요.
- 4×1 위젯이 주간·야간·휴무와 다음 근무를 현재 날짜에 맞게 표시하는지 확인해요.
- 백업 파일 저장·가져오기와 근무표 공유를 실제 파일로 확인해요.
- 앱을 하루 이상 열지 않은 뒤 다시 열어 날짜 변경, 다음 근무와 알람 예약이 갱신되는지 확인해요.

### 배포 완료

- 장기 보관 주소에 APK를 먼저 올리고 실제 다운로드와 SHA-256을 확인해요.
- `latest-android.json`은 APK 업로드와 검증이 끝난 뒤 마지막에 교체해요.
- 설정의 앱 업데이트에서 운영 주소의 APK를 한 번 더 내려받아 설치 화면까지 확인해요.
- 문제가 생기면 되돌릴 수 있도록 직전 운영 버전 폴더와 배포 기록을 보존해요.
